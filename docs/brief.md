# «Семь ночей» — бриф проекта (2026-09-18)

Автор брифа: оркестратор (Claude) по итогам разговора с владельцем (Константин Карпушин, CEO Codebridge).
Исходное ТЗ специалиста — `docs/tz-original.txt` (извлечено из PDF «Бот-компаньон „Семь ночей“. Подробно»).

## Что строим

Telegram-бот-компаньон для программы аудиопрактик + админка + лендинг на русском.
Главная цель владельца, дословно: **«чтобы этот бот вызывал вау-эффект и чтобы пользовательский опыт был очень простой»**.

Три поставляемых части:
1. **Telegram-бот** (`@ensoma_robot`, токен есть) — ведёт человека 7 вечеров подряд.
2. **Админка** — вся история и статистика + загрузка/редактирование текстов и аудио практик, текстов сообщений бота.
3. **Лендинг** на русском языке — отдельная страница, продающая программу (кнопка → бот).

Плюс: **аудио-заглушки** практик, озвученные через ElevenLabs подходящим (женским, спокойным, русскоязычным) голосом. Настоящий специалист потом заменит их своим голосом через админку. Заглушки должны звучать как настоящие практики, чтобы демо давало вау-эффект.

## Что ВЫПИЛИВАЕМ из ТЗ (решение владельца)

- Оплата (Продамус), страница «спасибо», коды доступа, проверка кодов по списку — **не делаем**. Вход в бота свободный: `/start` → онбординг.
- Технические рамки ТЗ (Vercel free tier, вебхук, «встроенный планировщик без сервера», бесплатные тарифы) — **не действуют**. Хостим на своей машине как systemd --user сервис, планировщик — свой, в процессе.

## Что ОСТАЁТСЯ из ТЗ (каркас)

- 7 вечеров подряд, каждый вечер одна аудиопрактика. Человек ложится, наушники, слушает.
- Человек выбирает удобный час (например 21:00) — бот пишет в это время.
- Каждый вечер: (1) замер «до» 0–10 → (2) практика (аудио + две строки текста) → (3) замер «после» по кнопке «Я сделал(а)» или через 20 минут → (4) «Записала. До завтра».
- Седьмой вечер: после второго замера — **картинка с графиком** (7 вечеров, две линии «до» и «после») + итог «Было 4. Стало 7.» + приглашение на разговор (30 минут, ссылка).
- Бот помнит минимум: час, текущий вечер, по каждому вечеру цифры до/после и дату. Ни имени, ни телефона, ни почты.
- Пропуск вечера: бот не ругается, программа сдвигается, человек проходит все 7 практик. Текст: «Вчера не получилось, это нормально. Продолжим с того места, где остановились?»
- Пауза / Продолжить.
- Не цифра в ответ → мягко просит цифру 0–10.
- Уведомления владельцу: человек начал программу; дошёл до 7-го вечера (с итогом «было/стало»); не открывал бота 3 дня подряд.
- Цифры: сколько начали; сколько дошли до 7-го; средний прирост между первым и последним вечером; на каком вечере чаще всего останавливаются.
- Приёмка: (1) тестовый прогон всех 7 вечеров в ускоренном режиме, где вечер идёт пару минут; (2) пропуск вечера → программа сдвинулась, а не пропала; (3) на 7-м вечере график и итог; (4) уведомления и цифры видны.
- Тон сообщений: короткие, тёплые, без восклицательных знаков, на «ты», от женского лица («Записала», «Открыла тебе»). Черновики из ТЗ можно брать как есть.

## Что ДОБАВЛЯЕТ владелец (ответы на вопросы 2026-09-18)

**Тема практик — шире, чем «только сон». Выбор по состоянию.** Дословно: «настроиться на предстоящий день, может быть важный диалог… можно выбрать по состоянию. И, конечно же, сон и расслабление там тоже есть, и тревога, и стресс. То есть с утра это может быть тревога и стресс, а может быть и вечером. И сон и расслабление точно перед сном.»

Вытекающая механика (решение оркестратора, детали — за проектировщиками):
- **Каркас 7 вечеров остаётся** — это стержень, замеры и график привязаны к нему.
- **Библиотека практик с категориями по состоянию**, минимум три:
  1. 😴 Сон и расслабление — вечер, по умолчанию.
  2. 🌿 Тревога и стресс — утро или вечер.
  3. 🌅 Настроиться на день / важный разговор — утро.
- Вечером бот после замера «до» предлагает выбрать состояние (кнопки), либо сразу даёт «сон», если человек не хочет выбирать — проектировщики решают, как сделать это максимально просто.
- **«Практика сейчас»** — кнопка/команда в любое время дня (утро!): выбор состояния → практика → замер до/после. Это вне 7-вечернего счётчика, но пишется в историю и статистику.
- Специалист загружает практики в админке: категория, название, две строки текста, аудио. Заглушки: ~8–9 практик (сон ×3–4, тревога/стресс ×2–3, день/разговор ×2).

**Хостинг**: пока tailnet (эта машина, `100.91.124.2:<порт>`), публичный домен позже.

## Окружение и технические решения (оркестратор)

- Машина: Hetzner VPS, Ubuntu, Node 22.22, Python 3.12, ffmpeg 7 (`~/.local/bin/ffmpeg`), Tailscale `100.91.124.2`. Свободный порт для сервиса: **3700**.
- Секреты: `~/.claude/secrets/seven-nights.env` (TELEGRAM_BOT_TOKEN), `~/.claude/secrets/elevenlabs.env` (ELEVENLABS_KEY_2..6 — 5 свежих бесплатных аккаунтов по 10 000 знаков; KEY_1 и ELEVENLABS_API_KEY исчерпаны). Никогда не коммитить. Проект использует свой `.env` (в .gitignore).
- **Стек** (решено): Node 22 + TypeScript (`tsx`), Telegram — **grammY**, БД — **SQLite** (`better-sqlite3`), HTTP — **Hono** (`@hono/node-server`), админка — **React + Vite + Tailwind**, графики в админке — Recharts, картинка графика для бота — SVG → PNG через `@resvg/resvg-js` (шрифт Noto Sans есть в системе, лучше положить .ttf в репо). Один процесс: бот (long polling) + планировщик + HTTP-сервер (админка + лендинг). systemd --user unit. Long polling, не webhook.
- **Состояние — только в БД** (state-машина по колонке `state` + `due_at` для отложенных шагов). Перезапуск процесса ничего не теряет. Планировщик — тик раз в 30 секунд по БД.
- **Часовой пояс**: Telegram не сообщает TZ. Нужно решение без трения (варианты: спросить «сколько сейчас у тебя на часах?» и вычислить смещение; кнопки городов; Web App с Intl). Проектировщики выбирают, приоритет — простота.
- **Аудио**: MP3 в `content/audio/`, при первой отправке загружаем в Telegram, кэшируем `file_id` в БД, дальше шлём по `file_id` (как в ТЗ).
- **Ускоренный (демо) режим**: флаг на пользователе (включается в админке или командой), при котором «20 минут» = 1 минута, «следующий вечер» = через 2–3 минуты, чтобы пройти 7 вечеров за ~15 минут. Нужен для приёмки и для демо владельцу.
- **Уведомления владельцу**: Telegram ID администраторов задаётся в админке (и/или env), бот отвечает на `/whoami` своим ID.
- Язык всего: русский. Кодовая база: английские идентификаторы, комментарии по-русски допустимы.

## Что должно быть «вау»

Открытый вопрос для проектировщиков. Кандидаты: график в конце с итогом «было/стало»; мгновенная реакция на цифру (например, «Записала: 4» с мини-полоской прогресса); тёплый и очень короткий копирайт; никаких меню и настроек — только кнопки в нужный момент; итоговая карточка-картинка, которой хочется поделиться; звук практики «ложится» с первых секунд.

## Дополнение 2026-09-18 (после запуска волны проектирования): тест на лендинге

Владелец переслал от куратора Ивана тест «Индекс внутренней опоры»: 7 вопросов, каждый — **ползунок 0–10** с двумя подписями, подсчёт индекса (сумма ÷ 70 × 100) и один из пяти текстов результата + обязательный дисклеймер. Полная спецификация с дословными текстами — `docs/quiz-spec.md`. **Лендинг должен быть интерактивным: человек проходит тест прямо на странице, видит результат и по кнопке уходит в бота** — это начало движения в бота. Результат передаётся в бота через deep link `?start=q<сумма>`; бот сохраняет индекс, админка его показывает. Детали и опциональный повтор теста после 7-го вечера — в quiz-spec.md.
